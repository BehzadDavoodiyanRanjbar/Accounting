# رابط کاربری جدید (React + Ant Design + TanStack Table)

> **وضعیت: روی Docker و Windows Server شما بالا آمده است؛ صفحه‌های جدید این مرحله (قالب کامل، اطلاعات پایه) هنوز روی کامپیوتر شما build و تست نشده‌اند.**
> محیط ساخت من اجازهٔ دانلود بسته‌های Ant Design و TanStack را نداشت؛ پس این پروژه اینجا اجرا و build نشده است. فقط این‌ها تست شده‌اند: بخش «آداپتور جدول» (۹ تست) و بخش «سرو شدن روی /v2» در سرور. بقیه (صفحه‌ها و DataTable) را اولین بار روی کامپیوتر خودتان build می‌کنید و ممکن است چند خطای تایپ یا ظاهر داشته باشد؛ خطاها را برای من بفرستید تا اصلاح کنم.

## نسخهٔ ۳۰ — OCR سمت سرور (جایگزین OCR داخل مرورگر)

- OCR داخل مرورگر (WebAssembly) حذف شد؛ چون به CSP، Worker، کش و فایل‌های زبان حساس بود و روی دو سرور متفاوت رفتار می‌کرد. اکنون مرورگر تصویر صفحه را به **همین سرور** می‌فرستد و **Tesseract نصب‌شده روی سرور** (فارسی+انگلیسی) آن را می‌خواند. PDFها هنوز در مرورگر با PDF.js به تصویر/متن تبدیل می‌شوند.
- داده‌ی زبان همراه برنامه است (`app/tessdata`). فقط خودِ برنامهٔ tesseract باید نصب باشد: **Docker** ← در `Dockerfile` خودکار نصب می‌شود (با `start.bat` دوباره ساخته می‌شود)؛ **ویندوز سرور** ← یک‌بار `install-ocr.ps1`.
- عملیات جدید سرور: `ocrStatus` (آیا آماده است؟) و `ocrImage`؛ نیاز به ورود دارند، هم‌زمانی ۲ و محدودیت تعداد دارند.
- فایل‌های `public/ocr` دیگر فقط PDF.js دارند (حجم بسیار کمتر).

## نسخهٔ ۲۹ — کارکنان شرکت (کاربران با دسترسی محدود)

- مدیر شرکت (کاربر اصلی هر شرکت) از منوی «سیستم ← کاربران شرکت (کارکنان)» کارکنانش را با ایمیل دعوت می‌کند. کارمند از پیوند ایمیل (آدرس `/invite`) نام کاربری و رمز خودش را می‌سازد.
- دسترسی هر کارمند: نقش آماده (حسابدار، کارشناس فروش، کارشناس خرید، انباردار، مسئول تولید، مسئول بهای خدمات، مسئول بانک، فقط مشاهده) + شخصی‌سازی بخش‌به‌بخش با سه حالت «بدون دسترسی / مشاهده / مشاهده و ویرایش». ده بخش: داشبورد، اطلاعات پایه، خرید، فروش، انبار، تولید، بانکداری، حسابداری، بهای خدمات، ثبت از روی اسکن.
- اعمال دسترسی **سمت سرور** است (منوی مخفی فقط ظاهر است). هر عملیات ناشناخته برای کارمند ممنوع است. «تنظیمات»، «پشتیبان‌گیری»، «ورود از Excel»، پروفایل شرکت، کلید/گواهی مؤدیان، حساب‌های پنل مشتری و مدیریت کاربران فقط برای مدیر شرکت است.
- سقف تعداد کارکنان ندارد (حداکثر ۲۰۰ کاربر و دعوت برای هر شرکت). اگر ایمیل (SMTP) تنظیم نباشد، پیوند دعوت روی صفحه نشان داده می‌شود تا مدیر شرکت خودش بفرستد.
- مدیر شرکت می‌تواند دسترسی را تغییر دهد، حساب را غیرفعال کند و رمز موقت بگذارد. حساب خود مدیر شرکت فقط با مدیر سیستم تغییر می‌کند. تغییر پایگاه‌داده لازم نیست.

## نسخهٔ ۲۸ — OCR داخلی، منوی قابل اسکرول، ادغام اسکن خرید

- **ثبت از روی اسکن** (حقوق، پرداخت به کارکنان، حق بیمه) دیگر هیچ هوش مصنوعی یا سرویس بیرونی ندارد. تصویر و PDF با **OCR داخلی نرم‌افزار** (Tesseract با زبان فارسی+انگلیسی، اجرا در همین مرورگر) خوانده می‌شود؛ PDFهای دارای متن مستقیم از لایهٔ متنی خوانده می‌شوند. جدول خوانده‌شده دقیقاً مثل فایل Excel نگاشت ستون و بررسی ردیف‌به‌ردیف می‌شود؛ ردیف‌های OCR همیشه اطمینان زیر ۰٫۸۵ دارند و باید «بررسی شد» بخورند.
- **اسکن اسناد خرید** منوی جدا ندارد؛ تب «سایر اسناد (خرید)» همین صفحه است (هنوز همان سازوکار قبلی را دارد).
- منوی کناری در صفحه‌های کوچک اسکرول دارد (منوی کشویی موبایل هم).
- فایل‌های موتور OCR با `npm install` از بسته‌های npm به `public/ocr` کپی می‌شوند (اسکریپت `scripts/copy-ocr-assets.mjs`) و با `npm run build` وارد `dist/ocr` می‌شوند؛ آدرس نهایی `/v2/ocr/`. حجم تقریبی ۳۰ تا ۶۰ مگابایت است.
- **صادقانه:** OCR فارسی روی کامپیوتر من اجرا و تست نشده (محیط من اینترنت npm ندارد). منطق تبدیل کلمه‌ها به جدول و الگوهای فیش بیمه با داده فرضی تست شده‌اند، ولی دقت واقعی روی فایل‌های شما باید با نمونه‌های حقیقی تنظیم شود.

## ساخت (Build) روی کامپیوتر خودتان

پیش‌نیاز: Node.js نسخهٔ ۲۰ یا بالاتر (از nodejs.org) و اینترنت.

۱. پوشهٔ `web` را هر جا که می‌خواهید قرار دهید (به پوشهٔ `app` وابسته نیست).
۲. در پوشهٔ `web` یک Command Prompt یا PowerShell باز کنید و به ترتیب بزنید:

```
npm install
npm run typecheck
npm test
npm run build
```

۳. بعد از `npm run build` پوشهٔ `web\dist` ساخته می‌شود.
۴. محتوای `dist` را در پوشهٔ `app\public\v2` کپی کنید (اگر `v2` وجود ندارد بسازید). فایل `index.html` باید مستقیم داخل `v2` باشد. مثال در PowerShell:

```
robocopy dist ..\docker\app\public\v2 /E
```

(مسیر مقصد را مطابق پوشهٔ خودتان عوض کنید.)

هر مرحله که خطا داد، متن خطا را برای من بفرستید.

## اجرا

- **نسخهٔ Docker:** `stop.bat` ← `start.bat` (پوشهٔ `v2` داخل `app\public` باشد تا در image برود) ← در مرورگر ابتدا وارد شوید، بعد آدرس `http://localhost:3000/v2/` را باز کنید.
- **Windows Server:** ابتدا فایل zip جدید سرور را با `update.ps1` نصب کنید (چون `server.js` عوض شده). بعد پوشهٔ `v2` را داخل `C:\MoinTaraz\app\public\` کپی کنید؛ نیازی به راه‌اندازی مجدد نیست.
- آدرس رابط جدید: `/v2/` (اگر هنوز نصب نشده باشد، پیام «هنوز نصب نشده است» دیده می‌شود).

## افزودن یک صفحهٔ جدید با جدول

1. در `src/api/` تابع‌های خواندن/ذخیره/حذف را بنویسید.
2. ستون‌ها را با `ColumnDef` تعریف کنید و در `meta` بنویسید: `label`، `filterType` (text/number/date/select/multiselect)، `numeric`، `width`.
3. وضعیت جدول را با `useTableQueryState()` بگیرید و `<DataTable />` را رندر کنید (نمونه: `src/pages/ContractsPage.tsx`).
4. صفحه را در جدول `NATIVE` فایل `src/pages/ViewRoute.tsx` با شناسهٔ بخش (مثلاً `cs_cc`) ثبت کنید؛ منو از `src/layout/menu.ts` ساخته می‌شود. برای اطلاعات پایه‌ای ساده فقط یک تعریف در `src/pages/entities/config.ts` کافی است.

منطق مخصوص هر ماژول (نام API، فیلدها، دکمه‌های عملیات) هرگز داخل DataTable نوشته نمی‌شود.

## قرارداد پرس‌وجوی جدول و آداپتور

```ts
interface TableQuery {
  page: number; pageSize: number;
  sorting: Array<{ id: string; desc: boolean }>;
  filters: Array<{ id: string; value: unknown }>;
  globalFilter?: string;
}
```

- `toBackendRequest()` در `src/adapters/tableQuery.ts` این query را به درخواست بک‌اند (`field`, `op`, `dir`) ترجمه می‌کند. شناسهٔ ستون لزوماً نام فیلد بک‌اند نیست؛ نگاشت صریح لازم است.
- **محدودیت فعلی (صادقانه):** APIهای فعلی برنامه (مثل `csList`) همهٔ رکوردها را یک‌جا برمی‌گردانند و بک‌اند هنوز صفحه‌بندی/مرتب‌سازی/فیلتر سمت سرور ندارد. تا آن زمان `applyLegacyQuery()` همین کارها را روی آرایه انجام می‌دهد و خروجی‌اش همان شکل پاسخ سمت‌سرور (`rows` + `total`) است. برای جدول‌های بسیار بزرگ (ده‌ها هزار ردیف) باید API سمت‌سرور ساخته شود؛ آن‌وقت فقط منبع داده عوض می‌شود و DataTable دست نمی‌خورد.

## نکتهٔ سال مالی (نسخه ۱۴)
فهرست «فاکتورهای خرید»، «فاکتورهای فروش» و «لیست اسناد حسابداری» به‌طور پیش‌فرض فقط فاکتورهای **سال مالی انتخاب‌شده** را نشان می‌دهد (تاریخ «از/تا» خودکار پر می‌شود). برای دیدن همهٔ سال‌ها، دو کادر تاریخ را پاک و «اعمال فیلتر/جستجو» را بزنید. شمارهٔ نسخهٔ رابط بالای صفحه (کنار نام کاربر) نوشته شده است.

## نمایش اعداد (نسخه ۱۴)
- **ارقام فارسی:** فونت برنامه (`public/fonts/Vazirmatn-*.ttf`) طوری ساخته شده که هر رقم لاتین را با شکل فارسی نشان می‌دهد؛ در همهٔ صفحه‌ها، کادرها و حتی بخش‌های قدیمی داخل قاب. مقدار ذخیره‌شده و محاسبات همچنان لاتین است و فایل‌های CSV/Excel تغییر نمی‌کنند.
- **جداکنندهٔ سه‌رقمی:** همهٔ کادرهای عدد و مبلغ (فاکتور خرید و فروش، سند حسابداری، دریافت و پرداخت، فرم‌های پایه) هنگام تایپ از راست سه‌رقم‌سه‌رقم جدا می‌شوند و ارقام فارسی را هم می‌پذیرند (`src/kit/NumInput.tsx`).
- **بدون اعشار:** مبالغ در گزارش‌ها و جدول‌ها بدون اعشار (گرد‌شده) نمایش داده می‌شود؛ مقدار کالا (تعداد/موجودی) تا ۳ رقم اعشار در صورت لزوم. در فرم ویرایش سند حسابداری دقت مبلغ (تا ۲ رقم اعشار) حفظ می‌شود تا مبلغ سند بی‌صدا گرد نشود. (`fmtNum` و `fmtQty` در `src/kit/format.ts`)
- اعداد راست‌چین‌اند و علامت منفی درست کنار عدد نشان داده می‌شود.


## پنل مشتری (آدرس /portal)
- صفحهٔ جدا برای خریداران شرکت؛ ورود با نام کاربری و رمز جدا (حساب نقش «customer»، جدا از کاربران شرکت).
- ساخت حساب: منوی «فروش ← حساب‌های پنل مشتری» (مدیر یا کاربر همان شرکت). رمز موقت ساخته می‌شود و خریدار در اولین ورود باید رمز بگذارد.
- خریدار فقط داده‌ی خودش را می‌بیند: نمای کلی، فاکتورها (با جزئیات و پرداخت‌ها)، صورت‌حساب (چاپ/CSV) و چک‌ها. فاکتور پیش‌نویس و ردشده نمایش داده نمی‌شود. پرداخت آنلاین ندارد.
- امنیت: حساب مشتری به هیچ عملیات برنامهٔ اصلی دسترسی ندارد؛ سرور فقط ۶ عمل پنل را برای او اجرا می‌کند و هر خروجی فیلد‌به‌فیلد ساخته می‌شود.
- build دو ورودی دارد: index.html و portal.html (هر دو داخل dist و سپس app/public/v2).

**بازگردانی پشتیبان (فقط مدیر):** منوی سیستم ← بازگردانی پشتیبان؛ بازگردانی تکی یک شرکت یا گروهی چند/همهٔ شرکت‌ها از فایل پشتیبان کامل یا پشتیبان یک شرکت؛ پیش از بازگردانی پشتیبان خودکار (restore-safety) گرفته می‌شود. سرور: actions backupList / restorePreview / restoreRun و مسیر POST /backup/upload.

## ثبت از روی اسکن (نسخه ۲۷)
- **منو:** گروه مستقل «ثبت از روی اسکن» زیر گروه «حسابداری» با دو زیرمنو: ۱) «ثبت از روی اسکن» (همان قابلیت قبلی فاکتور خرید، شناسهٔ `scan`، بدون تغییر؛ از گروه «خرید» جابه‌جا شد) و ۲) «حقوق، پرداخت و بیمه» (شناسهٔ `scan_doc`). سربرگ این دو صفحه مسیر «ثبت از روی اسکن · …» را نشان می‌دهد.
- **سه تب:** شناسایی هزینهٔ حقوق، پرداخت به کارکنان، پرداخت حق بیمه. ورودی: تصویر/PDF (با کلید هوش مصنوعی شرکت)، Excel/CSV (بدون هوش مصنوعی، روی سرور خودتان)، ورود دستی یا داده نمونه.
- **خروجی همیشه پیش‌نویس سند** است. سند قطعی ساخته نمی‌شود؛ تأیید نهایی با کاربر است.
- **کنترل‌ها:** واحد مبلغ (ریال/تومان) باید انتخاب شود؛ ردیف با اطمینان کمتر از ۸۵٪ تا «بررسی شد» مسدود است؛ اختلاف ناخالص−کسور≠خالص و اختلاف جمع‌ها مسدودکننده است؛ تطبیق تقریبی نام هرگز خودکار تأیید نمی‌شود؛ فایل تکراری (هش SHA-256) مسدود و شمارهٔ پیگیری تکراری هشدار است.
- **فایل‌ها:** `src/pages/scan/` (normalize.ts، rules.ts، extract.ts، sha256.ts، ReviewPanel.tsx، DocCapturePage.tsx و آزمون‌ها). سرور: `app/gs/Doc.gs` (actions docInit/docCheck/docExtract/docCommit/docSettingsSave و docParseXlsx در server.js) و جدول DocCaptures (در پشتیبان هر شرکت هست).
- نرخ‌های بیمه (۷٪ / ۲۰٪ / ۳٪) فقط پیش‌فرض قابل‌ویرایش‌اند؛ با حسابدار تأیید شوند.
